What Is an AI Agent?

Lectures 00 & 01 • Core concept — know this cold

💬 Chatbot / Instruction-Based

  • Human gives clear instructions
  • AI executes a single command
  • One-step action, no loop
  • Example: “Translate this sentence”

🤖 AI Agent / Goal-Based

  • Human gives a goal
  • AI figures out how to achieve it
  • Multi-step reasoning loop
  • Example: “Research X and write a report”

Perceive — Gather information about the current state of the environment. What is happening right now?

Think & Plan — Reason about the situation. Analyze, break the problem into steps, decide on a plan. The LLM is the “brain” here. Powered by language model reasoning.

Act — Take an action that changes the environment: call an API, run code, send a response, use a tool.

Observe — Receive feedback from the environment. This becomes the next observation, feeding back into perceive.

Learn — Update memory. Improve future decisions. Note: LLMs do not actually update their weights during agent execution—learning here means updating working memory/context.

💡

Professor’s framing: Building an agent is like building a small organization/company. Every agent is a person (engineer) with a specific function. Divide up the task, ensure proper communication, orchestrate to form an independent entity. Understanding how people work and organizations function is key to good agent design.

🚗Self-Driving Car as the Classic Agent Example

Goal: Get from point A to point B • Actions: Steer, brake, accelerate • Environment: The road/world • Observations: Sensor readings (stationary & moving objects)

Components: Sensing (perceive raw data) → Perception (interpret data into a world model) → Reasoning & Control (path planning, speed control). The system maintains a world view—a representation of the environment that enables simulation-based planning.

LLM as Agent

Lectures 01 & 02 • Why LLMs fit naturally into the agentic framework

🤔The Core Insight: Sequence-to-Sequence

An LLM is fundamentally a sequence-to-sequence model: given an input token sequence, it generates the next token. This maps perfectly to an agent loop:

  • Goal → described as text
  • Observation → also text
  • Action → generated text (which can invoke tools, APIs, code)

As long as something can be described in text, an LLM agent can work with it. This gives LLM agents virtually unlimited capability scope compared to traditional RL agents.

🎯 RL Agent

  • Highly optimized for its specific task
  • Limited capability scope
  • Requires explicit reward function
  • Cannot explain itself in natural language
  • Example: AlphaGo

🧠 LLM Agent

  • Virtually unlimited capability (text-describable)
  • Diverse scenarios without retraining
  • Reasoning limited by “token reasoning”
  • Can call external tools for things it can’t do alone
  • No deep search like chess engines
⚙Tool Use in LLM Agents

An LLM agent can decide that to complete a planned action it needs to call an external tool. Tools can be:

Python scripts Search engines Database queries API calls Code executors

The agent’s tool library itself can be managed with an AI retrieval system — query a “toolbox AI” for the top-N most relevant tools for the current task. This is called RAG-MCP (retrieval-augmented tool selection).

📋

LLM as Python programmer: With RL, an execution error gives reward −1 and retraining is needed. With an LLM agent, you just send it the error log and have it fix the error automatically—no retraining required. This illustrates the power of natural language as an interface for error handling.

📋Knowledge Trade-off in Agent Design

When designing an agentic system, a key architectural decision is: how much knowledge to put explicitly into the system vs. leaving to the LLM?

  • More knowledge in the system context → less reliance on LLM’s internal knowledge
  • Less knowledge in context → agent must rely more on what the LLM learned during training

This trade-off matters especially for domain-specific (e.g., semiconductor) data that the LLM was never trained on.

Context Engineering

Lecture 02 • The modern evolution of prompt engineering

⚠

Key Distinction: Prompt engineering is about finding magic words or phrasing that improves LLM output. Context engineering is the automatic management and curation of everything in the context window—selecting, compressing, and organizing information so the LLM receives the right input without being overloaded.

📄What Goes Into the Context?
ComponentDescription
System PromptIdentity, instructions, attitude, rules, formatting, safety constraints. Set by developers. Always the first part of the sequence. Defines behavior for every conversation.
User PromptThe actual request, including any in-context examples (few-shot)
Dialogue HistoryPrior turns in the conversation
MemoryLong-term saved facts; retrieved episodic memories
Retrieved InfoInternet search results, database results, documents (via RAG)
Tool ResultsOutput from tools the agent has called
ReasoningChain-of-thought scratchpad; planning steps (often hidden from user)
🔡Three Strategies for Context Engineering
  • 1

    Select (RAG) — Don’t dump everything into context. Use a retrieval system to pick only the most relevant documents, memories, or tools. A small LLM can score relevance sentence-by-sentence before passing to the main agent.

  • 2

    Compress — Turn long conversation history into a continuously updated summary. Feed an LLM its own context and ask it to summarize; that shorter summary becomes the new history. Lossy: store the full version in a vector DB and retrieve when needed.

  • 3

    Multi-Agent Decomposition — Divide work among multiple agents, each with a smaller, focused context. A leader agent coordinates; sub-agents execute specific tasks. Minimizes communication complexity and prevents context explosion in any single agent.

💡

Aptitude vs. Reliability: Aptitude is the best-case ability to solve the task in N runs. Reliability is how consistently that performance is achieved across different multi-turn conversations. Reading millions of tokens does not equal understanding millions of tokens. When an LLM makes a wrong assumption early in a long conversation, it often fails to recover.

💬Agentic Workflow vs. AI Agent

Agentic Workflow

Follows a fixed SOP (Standard Operating Procedure). Steps are predetermined. Less flexibility; more predictable.

AI Agent

Self-decision-making. Plans its own steps. Interacts with environment iteratively until it reaches a satisfactory result.

Memory & RAG

Lecture 01 & 02 • How agents manage past experience without overloading context

💾The Memory Problem

An LLM’s context window is finite. Including all past experience is infeasible (and harmful—performance degrades when context is overloaded). But forgetting everything is also bad. The solution draws an analogy to HSAM (Highly Superior Autobiographical Memory): counterintuitively, forgetting allows normal function. The agent needs selective, relevant recall.

🔍RAG — Retrieval-Augmented Generation

Rather than storing all memory in the context, store observations and experiences in a vector database. At query time, embed the current context and retrieve only the most semantically similar past experiences.

User Input
→

→
Vector Search
→
Retrieved Context
→
LLM + Context

RAG is the architectural solution to the “digital HSAM” problem: give the agent a large memory bank but only surface what’s relevant.

📋Write → Reflect → Read

Before invoking RAG, the agent should reflect: given the current query, what do I actually need from memory? Key reflection questions:

  • Is this goal aligned with past experience?
  • Have I identified a previously-failed pattern?
  • Have I synthesized alternative actions?
  • Should I revise my future plan based on this?

This reflection-before-retrieval step improves the quality of what gets pulled from memory.

🌐Knowledge Graphs vs. Flat Vectors

A flat vector store is good at finding similar items, but misses relational structure. A knowledge graph captures connections between concepts: retrieving a hotel booking experience should also surface related restaurant booking experiences. Google published a foundational paper on knowledge graphs for search in 2012.

Knowledge Graph

A graph-structured representation of entities and their relationships. Enables relational retrieval beyond simple similarity—following edges to find contextually related information.

🔋

ChatGPT Memory types: Persistent memory—explicitly saved from user request, stored across conversations, used for personalization. Contextual memory—inferred from the current conversation without explicit user instruction.

Chain of Thought & Reasoning

Lecture 03 • How prompting unlocks multi-step reasoning

💭Chain of Thought (CoT) Prompting

Problem: Standard few-shot prompting (just input/output examples) fails on multi-step reasoning problems. The model guesses rather than reasons.

Solution: Include intermediate reasoning steps in the examples. The model learns to generate its own reasoning chain before producing an answer.

⚠

Critical finding: CoT only yields gains on models with ∼100B+ parameters. Below that threshold, the model lacks sufficient capacity to actually reason; CoT provides no benefit. This is an emergent capability.

Ablation results confirm it’s the semantics that matter, not the length:

  • Equations only (no words) → no gain over standard
  • Placeholder tokens matching length → no gain (length alone doesn’t help)
  • CoT placed after the answer → no gain (must come before the answer to guide reasoning)
👥Self-Consistency (SC)

Complex reasoning tasks often have multiple valid reasoning paths. Rather than taking a single answer, sample multiple reasoning paths (using higher temperature) and take a majority vote over the final answers.

Why it works: Correct reasoning paths are more likely to reach the correct answer. Incorrect paths tend to scatter across wrong answers. The correct answer emerges as the mode.

💡

Temperature controls how “relaxed” the sampling is—higher temperature = more diversity in reasoning paths. SC requires higher temperature to sample diverse paths, then aggregates them.

Limitations: SC only works for problems with a single correct answer. For free-form answers, use Universal Self-Consistency (USC): generate multiple responses, concatenate them, ask the LLM itself to identify the most consistent answer.

Cost: SC is expensive (multiple LLM calls), but you can pay more for a better answer.

🌳ReAct: Reason + Act

Interleaves reasoning (Thought) with external action (Act) and its result (Observation):

Thought
→
Action
→
Observation
→

↻

Why it beats pure CoT: CoT is fully internal—if the model hallucinations a fact, it just reasons incorrectly from that hallucination. ReAct fetches real information via search/tools, grounding reasoning in external reality.

⚠

Failure mode: If an action returns no information (non-informative action), the agent has nothing to reason from. Recovery is very difficult—the model has no new token input to work with.

Agentic AI Evolution

Lecture 03 • From prompting techniques to full agent frameworks

🔧Toolformer

Problem ReAct solved partially: ReAct searched key phrases but wasn’t general. LLMs still struggled with up-to-date factual lookup, precise arithmetic, and date calculations.

Toolformer’s insight: Train the model via self-supervision to learn which API to call and when to invoke it. The model proposes API calls during generation; the call is kept only if it improves next-token prediction accuracy. The model learns to use tools as a natural part of generation, not as a special mode.

Self-supervised tool learningWhen to call = key question
🔄Reflexion

Based on ReAct. Adds a dedicated self-reflection step as verbal reinforcement learning. Four components:

ComponentRole
ActorGenerates actions using state observations stored in memory
EvaluatorAssesses the quality of outputs produced by the actor
Self-ReflectionGenerates verbal self-reflections on what went wrong/right
MemoryShort-term (recent trial trajectory) + Long-term (accumulated experience)

Demonstrates that a sequence-to-sequence LLM can improve its performance gradually through verbal self-critique, without parameter updates. This is verbal RL—reinforcement via language rather than gradient descent.

💡

Reflexion is the starting point where the agentic concept as we know it today emerged (2023).

🧠HuggingGPT (Task Planning with Specialist Models)

Problem: Text-only LLMs can’t handle vision, audio, multi-modal tasks. Specialized expert models exist for these but have no unified interface.

Solution: Use the LLM as a central brain / controller. Treat every expert model’s API as describable in plain language. The LLM:

  • 1

    Task Planning — Decompose the task using demonstration-based parsing

  • 2

    Model Selection — Filter Hugging Face models by task type, rank by download count, select top-K candidates

  • 3

    Task Execution — Invoke selected models and collect results

  • 4

    Response Generation — Integrate results into a coherent reply

Key idea: language as a generic interface. The LLM doesn’t need to know every model’s internals—it just needs natural language descriptions of what each model does.

LLM Training Pipeline

Lecture 04 • Pre-training → SFT → RLHF

🏭The Three-Stage Pipeline
Pre-training
→
SFT
→
RLHF

Each stage uses the previous stage’s parameters as initialization. The professor’s analogy: Pre-training = undergrad (study every major), SFT = graduate school (specialize and apply), RLHF = real-world feedback (align with what people actually want).

📚Stage 1: Pre-training

Task: Predict the next token (the “word chain game”). Self-supervised: the training signal is derived from the data itself by masking/removing tokens.

Data: Massive internet text (e.g., FineWeb: 15 trillion tokens, 44TB). Reading at one page per 10 seconds would take ~4,756 years. Models are trained on everything they can possibly scrape.

Purpose: Build a broad world model. The LLM absorbs language patterns, facts, reasoning structures, causal relationships. It doesn’t yet know how to answer questions helpfully.

💡

Scale matters: More data and more parameters generally improve performance, but there is an optimal model size for a given data size. Increasing model capacity without adding data leads to diminishing or negative returns. Data quality also matters significantly—cleaning internet data substantially improves performance. LLMs can be used to help clean training data (bootstrapping).

Why couldn’t early pre-trained LLMs answer questions? Internet data doesn’t teach Q&A. The text “The highest mountain in the world is…” doesn’t immediately follow in training data. The model has the knowledge but doesn’t know how to retrieve/express it as an answer.

🏫Stage 2: Supervised Fine-Tuning (SFT)

Purpose: Teach the model the reasoning process to find and express knowledge—not to inject new knowledge. Very small dataset compared to pre-training (tens of thousands of examples).

Critical insight: SFT by itself is ineffective without pre-training. And SFT doesn’t work by teaching new facts—it works by unlocking the structure of knowledge already embedded in the pre-trained model.

💡

Why redundancy in pre-training matters: If a fact appeared in pre-training in only one form, SFT can’t easily surface it. If the same knowledge appeared in many different linguistic forms, the model built a graph of that knowledge—SFT can then tap into this graph to generalize. Pre-training requires lots of data partly for this reason.

What data works best for alignment?

  • Questions where the model might know the answer (not too easy, not unknown)
  • Diverse tasks, moderately difficult
  • Long examples (short examples lack sufficient information)
  • Non-redundant (representative, not repeated)
  • Inconsistent examples actually hurt performance
⚠

Key principle: Alignment is a data curation problem, not just a training problem.

🎯Stage 3: RLHF — Reinforcement Learning with Human Feedback

Unlike Stages 1 & 2 where loss is calculated per-token, RLHF calculates a reward for the entire answer. Human raters compare model outputs; their preferences train a reward model.

The main LLM is then fine-tuned using PPO (Proximal Policy Optimization)—a policy gradient algorithm—to maximize the reward model’s score.

RLAIF: Instead of human raters, use another AI model as the reward judge. Cheaper and scalable, but introduces alignment concerns about the judge model.

Why RL? We want to optimize for the whole response, not just each token. Correctness is often only determinable at the end of a response (like Go, where the outcome is known only at game end).

PPO (Proximal Policy Optimization)

A policy gradient RL algorithm that updates model parameters to maximize expected reward while keeping the updated policy close (proximal) to the original policy—preventing catastrophic forgetting or destabilization.

📋Do LLMs Use Logic or Probability?

Evidence suggests LLMs primarily follow probability, not pure logical reasoning. Example: GPT answers Rot13 cipher correctly (widely used in training data) but fails on Rot8 (rarely seen). If it were truly reasoning logically, both should be equally solvable. The model is pattern-matching from training distribution, not computing.

⚠

This has profound implications for reliability: LLMs can make errors on tasks that are logically identical to tasks they can solve, simply because the surface form looks different.

Meta-Learning & In-Context Learning

Lecture 04 • Learning to learn; learning without gradient updates

📈What Is Meta-Learning?

Regular learning: Given a dataset, train a model to perform a specific task. Architecture, initialization, and update rules are all defined by humans.

Meta-learning: Train a model not just on data, but on a family of tasks, so it learns how to learn—the underlying strategy for rapidly adapting to new tasks. The loss function is the sum of losses across many tasks.

Meta-Learning (Learning to Learn)

Training a model across a distribution of tasks so it develops general learning strategies. At inference time, the model can rapidly adapt to a new task from just a few examples, without retraining.

This is the conceptual precursor to in-context learning. Meta-learning developed before 2020; in-context learning emerged as its realization at scale in LLMs.

📋Siamese Networks (Support & Query)

A key meta-learning architecture. Uses a CNN to map inputs (images) to an embedding space. A support set (training examples) and a query (test input) are both embedded; the model checks whether their embeddings are similar.

In the embedding/code space, similarity = same class. This is related to BERT: encode inputs into abstract representations, then reason about similarity in that space. This maps to RAG: embed queries and memories, retrieve similar ones.

💭In-Context Learning (ICL)

The modern realization of meta-learning in LLMs. Provide examples directly in the prompt; the model adapts to the task without any parameter updates.

Fine-Tuning (Old Way)

  • Requires labeled dataset
  • Updates model weights
  • Time-consuming
  • Risk of overfitting

In-Context Learning (ICL)

  • Examples in prompt only
  • No weight updates
  • Instant adaptation
  • Limited by context size
💡

Scale matters for ICL too: In-context learning abilities improve dramatically with model scale. A small model cannot leverage demonstrations effectively; a large model can generalize from very few examples.

Density Estimation

Lecture 05 • The mathematical foundation behind generative models

📊The Core Problem

Given a set of observed data samples, estimate the probability distribution p(x) that generated them. Or better: estimate the generator that produces that distribution.

Density Estimation

The task of estimating the underlying probability distribution of observed data. Enables generating new samples, detecting anomalies, and understanding data structure.

🎗Parzen Windows (Non-Parametric)

Treat every data point as the center of a small Gaussian distribution. Sum all Gaussians; normalize. Points clustered together produce high density; spread points produce lower density. Works in multiple dimensions.

Critical limitation: This is modeling, not learning. It can only describe data it has seen. It cannot extrapolate to unseen regions of the input space. True learning requires generalization—the ability to assign probabilities to points never seen in training.

⚠

Professor’s distinction: Modeling = creating a description of seen data. Learning = generalizing to unseen data. Don’t confuse them. Applying a Gaussian assumption and computing sample mean/variance is modeling—it assumes normality without checking.

📈Maximum Likelihood Estimation (MLE)

Assume p(x) = fθ(x) parameterized by θ. Find the θ that maximizes the probability of observing the training data. Because the joint probability of all samples is tiny, we maximize the log-likelihood instead (log converts products to sums).

Example: Assuming Gaussian distribution, MLE gives us the sample mean and sample variance. But this bakes in the Gaussian assumption—you must first verify the distribution looks Gaussian.

🔳Latent Variables: Learning the Generator

Instead of directly modeling p(x), model the mechanism that generates p(x). Introduce latent variables z (unobserved causes) that drive the data generator.

Gaussian Mixture Model (GMM)

A generative model where: (1) sample a component m from a multinomial distribution, (2) sample x from a Gaussian conditioned on m. The observed data is a mixture of multiple Gaussian sources. p(x) = Σ P(m) P(x|m). More Gaussian components = greater modeling capacity.

Moving from flat density estimation to latent variable models is the key step toward deep generative models (VAE, GAN, diffusion, LLMs).

Latent Variables & VAE

Lecture 05 • Variational inference and the evidence lower bound

🔳Variational Inference

To infer latent z from observed x, we want p(z|x). This is intractable to compute directly. Variational inference finds an approximation q(z) from a tractable family of distributions by minimizing the KL divergence between q(z) and p(z|x).

KL Divergence (Relative Entropy)

A measure of how different two probability distributions are. KL(q||p) = 0 when q = p. Asymmetric: KL(q||p) ≠ KL(p||q). Used to measure how well an approximating distribution q matches the true distribution p.

This converts a function calculation problem (find p(z|x)) into an optimization problem (minimize KL divergence over a parameterized family). That makes it tractable for neural networks.

📈Evidence Lower Bound (ELBO)

We want to maximize log p(x) (the probability of our data). This decomposes as:

log p(x) = ELBO(q) + KL(q(z) || p(z|x))

Since KL ≥ 0, ELBO ≤ log p(x)—it’s a lower bound. Maximizing ELBO simultaneously: (1) makes the generated data more likely, and (2) makes q(z) closer to the true posterior p(z|x). We can maximize ELBO without computing the intractable p(z|x) directly.

🔄Variational Autoencoder (VAE)

Variational Principle → Variational Method → Variational Inference → VAE (amortized with NN)

A VAE uses neural networks to implement variational inference at scale:

  • 1

    Encoder: q(z|x) — Maps input x to parameters μ(x), Σ(x) of a Gaussian in latent space

  • 2

    Sampling: Sample z from N(μ, Σ). Reparameterization trick: z = μ + Σ·ε where ε ~ N(0,1). Enables backprop through the sampling step.

  • 3

    Decoder: p(x|z) — Reconstructs x from sampled z. The actual learning happens here.

ELBO for VAE = reconstruction accuracy (decoder loss) − KL(q(z|x) || p(z)). Simultaneously optimize reconstruction quality and keep the latent distribution close to a Gaussian prior.

💡

Key difference from plain autoencoder: A regular AE compresses to a specific code. A VAE compresses to a distribution over codes, then samples from it—enabling generation of new samples by sampling from the prior.

Reparameterization trick: Sampling is non-differentiable. Rewrite z = μ(x) + Σ(x) · ε (ε is a fixed noise input). Now gradients can flow through μ and Σ during backprop.

🌐Connection to LLM Training

The professor draws a deep analogy: LLM training can be understood as variational inference over a latent world state.

  • The latent variable z = the “world state” underlying the language (never explicitly modeled)
  • The Transformer is forced to infer this latent state internally
  • The world model is stored in the parameters θ (the decoder/transformation), not in z
  • Randomness (z) is just a seed; knowledge is in the transformation
💡

In VAE, learning happens in the decoder. Starting from maximum entropy (pure randomness), the VAE learns how to generate from nothing. If you can generate from pure randomness, you have learned the world. Knowledge is stored in the transformation, not the input.

Generative Adversarial Networks (GANs)

Lecture 05 • Adversarial training for generation

⚔The Core Idea

Two networks compete: a Generator and a Discriminator.

Generator

  • Input: random latent vector z
  • Output: synthetic image/data
  • Goal: fool the discriminator
  • Architecture: transposed CNN
  • More complex; trains longer

Discriminator

  • Input: real or generated sample
  • Output: real or fake label
  • Goal: correctly classify samples
  • Architecture: CNN with sigmoid
  • Simpler; trained fewer epochs
⚙Training Process
  • 1

    Train Discriminator: Feed real data (label=1) and generated data (label=0). Minimize classification error.

  • 2

    Train Generator: Generate samples; pass through (frozen) discriminator; minimize the discriminator’s ability to detect fakes. Gradient flows backward through discriminator into generator.

Stopping criterion: When the discriminator can no longer distinguish real from generated data (outputs ~0.5 for everything). Training is inherently unstable because the target keeps moving.

⚠

Failure mode: If the discriminator becomes too strong too fast, the generator receives vanishing gradients and cannot improve. Engineering tricks needed: batch normalization, Leaky ReLU, proper learning rate scheduling.

Each step improved generation quality. Diffusion models currently achieve near-ideal performance overall, overtaking GANs.

Amortized Variational Inference (in VAE/GAN context)

Instead of solving a separate optimization problem for each data point (expensive), train a neural network to perform approximate inference for all data points at once. “Amortized” = the optimization cost is spread across all examples.

Emergence & Compression

Lecture 05 • Why LLMs are so much more than next-token predictors

✨Where Does Intelligence Come From?

From a traditional ML view, maximizing likelihood (next-token prediction) should just produce a good density estimator—not an intelligent reasoner. So where does the intelligence come from?

💡

Key shift: The data distribution is natural language, and natural language is a projection of everything in the real world. When a model learns p(next token | context), it must implicitly learn:

Causality Physical Reasoning Human Intent Social Rules Logic Patterns

These are all encoded in language. Language is the most compressed representation of human knowledge.

📈Emergent Capabilities

Capabilities that appear suddenly and discontinuously as model size or training scale increases. They are not present in smaller models and cannot be predicted by extrapolating smaller-model performance.

Examples of emergent capabilities: Chain-of-thought reasoning (emerges at ~100B parameters), multi-step arithmetic, code generation, zero-day vulnerability discovery (in Anthropic models—never explicitly trained on this).

⚠

There is a large gap between what we can explain and what we have observed in LLM capabilities. Studying emergent behavior is difficult because it requires experimenting at large scale. The boundary of capabilities is blurry and continuously changing.

📌Kolmogorov Complexity View

Kolmogorov complexity of data = the length of the shortest program that generates it. Data can look complex, but if you learn the generator (via latent variables), you find a short program that produces the data distribution.

In the limit: learning everything = finding a short program that generates reality. That program takes a simple random seed as input. All knowledge is stored in the transformation (the model parameters), not the input.

💡

The professor’s insight on learning: True learning is not memorization (autoencoder-style). True learning means internalizing the transformation so completely that you can forget the original data and regenerate knowledge from “random.” Knowledge is in the transformation, not the input. When studying: don’t try to remember slides—learn the underlying principle and regenerate from first principles.

Key Definitions

All Lectures • Core vocabulary the professor expects you to know precisely

AI Agent
A system that perceives an environment, reasons about it, takes actions to achieve a goal, and learns from feedback—in a loop. Distinct from a chatbot: agents plan multi-step strategies, not just respond to single commands.
Sequence-to-Sequence (S2S)
A model that takes an input sequence and produces an output sequence. LLMs are S2S models: given token history, predict next token. All LLM reasoning is fundamentally S2S generation.
Context Engineering
The practice of automatically managing, selecting, and compressing what goes into an LLM’s context window to optimize performance and avoid overload. Evolved from prompt engineering.
RAG (Retrieval-Augmented Generation)
Architecture where a retrieval system selects relevant documents/memories from a large store and injects them into the context before generation. Enables long-term memory without overloading context.
Chain of Thought (CoT)
A prompting technique where intermediate reasoning steps are included in examples or generated by the model before the final answer. Unlocks multi-step reasoning in large models (≥100B params).
Self-Consistency (SC)
Sample multiple reasoning paths from an LLM and take a majority vote over final answers. Improves accuracy on tasks with fixed answers. Acts like an unsupervised self-ensemble.
ReAct
Prompting framework that interleaves Thought (internal reasoning) with Action (external tool call) and Observation (result), enabling grounded reasoning that avoids hallucination.
Hallucination
When an LLM generates plausible-sounding but factually incorrect text. Occurs because the model follows probability, not verified truth. Chain-of-thought can amplify hallucinations if a wrong fact is accepted early.
Pre-training
First stage of LLM training. Self-supervised next-token prediction on massive internet text. Builds broad world knowledge and language understanding. Does not directly teach Q&A or instruction-following.
SFT (Supervised Fine-Tuning)
Second training stage. Small curated dataset of instruction-answer pairs. Teaches the model to express its pre-trained knowledge in a helpful, instruction-following way. Does NOT inject new knowledge—unlocks existing structure.
RLHF
Reinforcement Learning with Human Feedback. Third training stage. Humans rate model outputs; ratings train a reward model; PPO optimizes the LLM against that reward. Reward is for the whole answer, not per-token.
PPO (Proximal Policy Optimization)
Policy gradient RL algorithm used in RLHF. Updates model parameters to maximize reward while keeping updates bounded (proximal), preventing catastrophic forgetting or training instability.
In-Context Learning (ICL)
Learning a new task from examples provided directly in the prompt, without updating model weights. The model’s behavior adapts purely from the context. Emerges at large scale.
Meta-Learning
Training a model on a family of tasks so it learns how to learn—developing general strategies for rapid adaptation to new tasks from few examples. Conceptual precursor to ICL.
Emergence
Capabilities that appear suddenly at scale and cannot be predicted from smaller models. Examples: CoT reasoning, code generation, zero-day vulnerability discovery. Result of the model internalizing complex world structure.
Variational Inference
Approximate Bayesian inference that turns intractable posterior computation into an optimization problem. Find the distribution q(z) closest (in KL divergence) to the true posterior p(z|x) within a tractable family.
KL Divergence
Kullback–Leibler divergence. Measures how much distribution q differs from distribution p. KL(q||p) ≥ 0; equals 0 only when q=p. Asymmetric. Used in VAE training to keep latent distribution near a Gaussian prior.
ELBO (Evidence Lower Bound)
A tractable lower bound on log p(x). Maximizing ELBO simultaneously improves data reconstruction and minimizes KL divergence between the approximate and true posteriors. Core objective of VAE training.
Latent Variable
An unobserved variable that causally generates the observed data. Introducing latent variables moves from directly modeling data to learning the generative process. Enables extrapolation to unseen data.
VAE (Variational Autoencoder)
A generative model using amortized variational inference. Encoder maps input to latent Gaussian parameters; reparameterization allows backprop through sampling; decoder reconstructs. Trained to maximize ELBO.
GAN (Generative Adversarial Network)
Two-network framework: Generator produces samples from random noise; Discriminator classifies real vs. generated. Training is adversarial. Stops when Discriminator can no longer distinguish real from fake.
Kolmogorov Complexity
The length of the shortest program that generates a given piece of data. A theoretical measure of information content. Insight: learning = finding the short program (in model weights) that generates the data distribution from a random seed.
Reflexion
Agentic framework adding verbal self-reflection to ReAct. Actor generates actions; Evaluator scores outputs; Self-Reflection generates verbal critique; Memory stores trajectory. Enables iterative improvement without retraining.
System Prompt
Instructions given to an LLM before any user interaction. Defines identity, rules, tone, formatting, and domain knowledge. Always the first part of the input sequence. Hidden from users; set by developers.
